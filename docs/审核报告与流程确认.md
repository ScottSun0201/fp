## 1. 系统核心：一句话

**LWFP = 骊威的供应商对账系统（采购方视角）。供应商寄来对账单，系统逐行跟 ERP 采购/到货数据核对，防止同一批货重复付款、多付钱。**

---

## 2. 系统灵魂机制：累计占用（防重复付款）

这是整个系统存在的意义，理解它才能理解所有流程：

```
同一行物料 按"供应商 + 物料编码 + 采购单号 + 单价" 组成唯一指纹
    → 跨【所有历史对账单】累计已对账的数量和金额
    → 拿累计 对比 ERP 的"到货数量 / 可对金额"

        累计 ≤ ERP到货量 且 金额 ≤ 可对金额  → PASS    ✅ 正常
        累计 > ERP到货量/金额               → 超额     🚨 重复对账!防的就是它
        单价 与 ERP 不一致                   → 超额     ⚠️ 价格有问题
        ERP 查不到这一行                     → 无记录   ⚠️ 需要核实
```

**业务含义**：同一批货，供应商只能对账一次。上次对过 100 个，这次又拿 100 个，累计 200 > ERP 到货 100 → 标超额，防重复付款。

## 3. 完整业务链路（v1 现状真实流程）

```
① 供应商寄来对账单（PDF/Excel/图片）
        ↓
② 财务上传系统（系统解析：订单号/物料/送货单/日期/数量/单价/金额）
        ↓
③ 必须从 ERP 选合作商（带编码，选不到不能继续）
        ↓
④ 系统逐行去 ERP 查采购订单 + 到货记录（阿里云只读库）
        ↓
⑤ 计算累计占用 → 每行得出：PASS / 超额 / 无记录
        ↓
⑥ 人工处理差异行（审核通过/忽略/上传发票核对/填写付款）
        ↓
⑦ 系统实时算状态：付款(未付/少付/多付/已付)、开票(未开/少开/多开/已开)
        ↓
⑧ 确认对账 → 已完成
        ↓
⑨ 看板：供应商统计/进度/超时预警(超30天未回款)
```

## 4. 审核发现：闭环断在哪（6 个断点）

| # | 断点 | 业务影响 |
|---|------|---------|
| 1 | 确认对账没门槛 | 有超额行没处理、没付款、没开票，也能直接点"确认对账"变已完成 |
| 2 | 人工处理不留状态 | "审核通过"只记一条说明，行还是标超额，看不出处理过没有 |
| 3 | 付款/开票只是记一笔 | 没有审核、没有顺序要求（先开票还是先付款都行） |
| 4 | 超额了怎么办没有闭环 | 标了超额就完了——是上次重复？本次多算？要不要冲销？没有处理动作、不关联历史 |
| 5 | 两套统计并存 | 预警/首页还在用旧"发票匹配"那套，跟实际用的"累计占用"没打通，数字对不上 |
| 6 | 跨月不直观 | 累计占用历史要点小弹窗才看到，没有页面一眼看到"这家供应商还剩多少可对" |

## 5. v2 流程确认版（含新增能力）

### 5.1 新增能力一：手动新增（不只是上传）

| 入口 | 现在的系统 | v2 要求 |
|------|-----------|---------|
| 新增对账单 | 只能上传文件 | **上传 或 手动录入**（选供应商、填期间、填明细） |
| 新增明细 | 只能靠解析 | **手动补行/改行/删行** |
| 新增供应商 | 只能从 ERP 选 | **手动登记 + 关联 ERP 编码**（找不到也能先建） |
| 付款/开票记录 | 处理时记一笔 | **独立入口手动新增**，可多次、可编辑 |
| 处理结论 | 只能选几种 | **手动备注 + 选动作 + 挂起原因** 全可填 |

> 原则：**系统能自动的就自动，自动不了的必须能手动补，两条路并存，殊途同归。**

### 5.2 新增能力二：多种查询汇总方式

| 维度 | 说明 |
|------|------|
| 按供应商查 | 一家供应商的全部对账单、差异、付款、开票历史 |
| 按月份/期间查 | 某月或自定义期间的对账情况（自然月/自定义区间） |
| 按状态查 | 待处理/处理中/已完成/已挂起 自由筛选 |
| 按差异类型查 | 超额/无记录/单价不符 分开看 |
| 组合查询 | 上面任意组合（如：A 供应商 + 7月 + 未完成） |
| 汇总统计 | 每种查询结果自动汇总：总金额/已对/未对/差异数/处理进度 |

> 原则：**所有列表页都能查、能筛、能汇总，导出 Excel。**

### 5.3 新增能力三：前端整体重构（参考 Geeker-Admin）

| 项 | 现在 | v2（参考 Geeker-Admin） |
|----|------|------------------------|
| 技术栈 | 原生 HTML+JS | **Vue3 + TypeScript + Element Plus + Pinia** |
| 布局 | 分散独立页面 | 统一后台布局（侧边菜单/顶部栏/面包屑） |
| 表格 | 简单列表 | 专业表格（筛选/排序/分页/行操作） |
| 表单 | 简单表单 | 校验完整、弹窗编辑 |
| 图表 | 少 | ECharts 看板（进度/占比/趋势） |
| 权限 | 基础 | 菜单级权限（沿用现有角色） |

### 5.4 核心闭环流程（v2 目标）

```
上传 或 手动新增 对账单
   ↓
选 ERP 供应商（可手动登记）
   ↓
解析 或 手动录入 明细
   ↓
逐行 ERP 核对（累计占用：PASS/超额/无记录）
   ↓
差异行必须有处理结论（动作 + 说明）
   ├─ 已解决 → 留痕
   └─ 挂起 → 必填原因 → 下月自动带入
   ↓
开票 + 付款（独立入口，可多次）
   ↓
【门槛】差异全部处理完 + 开票付款记录齐全 → 才能确认对账
   ↓
已完成 → 可追溯 → 看板汇总
```

## 5.1 已确认：手动新增 = 新建记录 + 多商品明细 ✅

- **新建一条对账单记录**（无需先传文件），记录本身带：供应商 / 对账期间 / 用途备注
- 这条记录下面**挂多个商品明细行**（订单号、物料、数量、单价、金额……），数量不限，可随时增删改
- 手动新建的记录与上传解析的记录**走完全相同的流程**：选 ERP 供应商 → 逐行核对 → PASS/超额 → 处理差异 → 开票付款 → 确认对账

## 5.1.1 已确认：明细录入方式 = 逐行填 + 粘贴批量 ✅

- **逐行填**：点"添加行"，一行行填订单号/物料/数量/单价/金额
- **粘贴批量**：从 Excel 复制几行，直接粘贴进来，自动变成明细（10 秒搞定）
- 两种方式**并存**，少的逐行填，多的粘贴，殊途同归

## 5.1.2 已确认：供应商必须来自 ERP，无 ERP 做不来 ✅（用户原话）

- **以 ERP 为根**：对账的供应商、物料、采购单、到货量、可对金额，**全部来自 ERP**
- 手动新增 ≠ 脱离 ERP，只是"录入方式"不同——**供应商只能从 ERP 主数据里选**，选不到就不能继续
- 没有 ERP 数据，对账就没有对比基准，**整个功能不成立**
- 上传与手动新增两条路，最终都汇入同一条 ERP 核对主流程

- **逐行填**：点"添加行"，一行行填订单号/物料/数量/单价/金额
- **粘贴批量**：从 Excel 复制几行，直接粘贴进来，自动变成明细（10 秒搞定）
- 两种方式**并存**，少的逐行填，多的粘贴，殊途同归
